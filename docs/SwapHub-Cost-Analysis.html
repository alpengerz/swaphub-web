Executive summary

SwapHub is already a working, responsive web prototype (10 screens, deployed and publicly accessible). This document estimates what it takes to turn it into a real product for a first cohort of ~1,000 users, the 5-year cost of running it as a native mobile app, and how a self-hosted AWS setup compares to managed services at that scale.

Key takeaways

  • The UI is done. Remaining work is wiring real data and backend logic, not redesigning screens.
  • Go PWA-first or Expo. One codebase covers web + iOS + Android; skip separate native builds to halve cost.
  • Managed services beat AWS at 1k users. Supabase / Cloudinary / Vercel free tiers cost near ₱0; raw AWS carries fixed monthly baseline plus DevOps labour.
  • Maintenance is the real 5-year cost of native apps — Apple/Google force yearly updates whether or not you add features.
  • Self-hosting only pays off at scale (roughly 50k–100k+ users), not at launch.
Recommended path
Build a lean, trade-only app on Supabase + Expo reusing this UI, launch a private beta to ~1,000 users, stay on free/managed tiers, and revisit AWS only if you reach real scale.

Why maintenance isn't optional for native apps
Even with zero new features, Apple and Google ship breaking OS updates yearly and change store policies. An app left untouched for 12–18 months typically breaks or gets delisted. Budget at least a light retainer (~₱15k–30k/mo) to stay installable and compliant. A single Expo codebase roughly halves this versus separate iOS + Android apps.

3   Self-hosting on AWS — does it lower cost?

Short answer: no, not at ~1,000 users. Raw AWS adds a fixed monthly baseline and ongoing DevOps labour. Managed/free tiers are near-zero at this scale. AWS only becomes cheaper per user at large scale (~50k–100k+ users) or when specific control/compliance is required.

The hidden cost is people, not servers
The AWS bill itself isn't huge, but self-hosting means someone must own security patching, database upgrades, backups, monitoring and scaling. That is the opposite of "minimal bug fixes" — it adds a standing DevOps responsibility that managed platforms absorb for you.

When AWS does make sense

  • You cross ~50k–100k+ active users and managed per-unit prices exceed AWS baseline + amortized DevOps.
  • You need specific compliance, data residency, or custom infrastructure managed platforms can't offer.
  • You already have in-house DevOps whose time is effectively "free" to the project.
  • Heavy, predictable workloads (large media/video, ML) where reserved AWS capacity beats usage-priced SaaS.
Recommendation: Stay on managed services (Supabase + Cloudinary + Vercel/Expo) for the early app. Design the backend cleanly so a future migration to AWS is possible — but don't pay the AWS complexity tax until real scale justifies it.

Recommended plan

  • Build: Trade-only app on Supabase + Expo, reusing the existing UI. Target 2–3 months, ₱400k–800k with one contractor (or your own time).
  • Launch: Private beta to ~1,000 invited users. PWA first if you want to validate before paying store fees; add native store builds once demand is proven.
  • Infrastructure: Managed/free tiers. Expect < ₱2k/month at this size. Do not self-host on AWS yet.
  • Maintenance: Light retainer (~₱15k–30k/mo) once on the stores, purely to keep up with OS and policy changes.
  • Revisit AWS only after ~50k+ users or a specific compliance need.
Total to get live and run for a year
Build (₱400k–800k) + one year of managed infra (~₱20k) + store/domain fees (~₱8k) ≈ ₱430k–830k for year one, or dramatically less if you build it yourself.
